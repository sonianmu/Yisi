# 更新授权迁移与软件修复

更新授权迁移与软件修复已实现。自动化测试使用独立偏好域和模拟权限命令，不会重置开发者本机的真实权限。真实跨版本覆盖升级与系统授权确认仍需在 macOS 上验证。

## 更新后的授权迁移（已实现）

- 新版首次启动读取版本及 Security 框架的 designated requirement，覆盖应用内更新和手动替换 App 两种情况。
- 临时签名身份改变时，自动刷新 Yisi 的辅助功能与录屏授权记录；无迁移记录的旧版用户首次升级到临时签名版本时，也执行一次。
- 稳定签名身份未改变时，版本更新只处理当前未获授权的项目；首次安装及普通启动不重置。
- 先持久化本次身份与待授权状态，再登记当前 App 并调用 `tccutil reset Accessibility/ScreenCapture com.sonianmu.yisi`。记录写入失败时不执行重置；普通重启不重试已处理的身份，避免循环。
- 权限重置命令限时运行。失败会记录结果并提示系统授权或 GitHub Issues；不隐瞒失败，不执行全局权限清理。
- 重置成功后只自动重启一次，清除进程缓存的权限判断；随后直接进入权限步骤，完成后进入主页，不再经过欢迎首页或 API 配置页。
- 不清除用户配置，不访问 Keychain，不打开或删除历史、截图、学习规则或预设文件。
- macOS 授权确认仍由用户完成，应用不能静默授予权限。
- 更新安装前校验 App 的 Bundle ID、可执行文件名和完整签名；替换采用备份与回滚，并通过位置参数传递路径，支持引号、空格等字符；`open -n` 启动精确 App。
- 自动化测试覆盖旧版迁移、签名变化、稳定签名、重复启动、迁移失败、中途退出、持久化失败、数据保留、命令作用域与更新回滚。

## 软件修复入口（已实现，发布前仍需验证实际权限与重启）

- 名称为“软件修复”，面向功能失效、配置异常和权限异常，不限于权限修复。
- 必须保留翻译历史数据库、历史截图和学习数据；不能直接复用 `fresh-start.sh --new`。
- API 密钥及配套服务地址、模型配置必须保留，修复功能不提供删除选项。
- 设置页和菜单栏右键菜单均提供入口；右键菜单也提供 GitHub Issues 入口。
- 只恢复外观、快捷键和弹窗位置；其他设置、预设及未知配置键均保留。
- 先将待重置的普通设置备份到 Application Support 下的 `com.sonianmu.yisi/RepairBackups`，缓存移入同一备份目录；备份失败则停止。
- 修复不访问钥匙串，不触碰历史数据库及其 WAL/SHM 文件，不删除截图或学习数据。备份中不额外复制 API 密钥。
- 缓存归档失败时尝试回滚已移动的缓存，并保留备份；普通设置尚未重置。
- 检查实际权限，仅尝试重置失效的辅助功能和录屏授权。系统确认仍需用户完成。
- 重启后打开主页或直接进入所需授权步骤，不从欢迎首页重新开始。
- 确认页说明可能丢失部分临时数据或个性化设置，同时明确 API 与历史的保留承诺。失败提示与设置页均引导到 GitHub Issues，不要求联系作者。
- 发布前验证旧版覆盖升级、授权拒绝、迁移失败和修复后历史可读的情况。
