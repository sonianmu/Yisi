## 更新后的授权迁移

- 以免费发布为前提，不要求购买 Apple 开发者账号。
- 更新流程自动处理 Yisi 自身的失效授权记录，避免要求老用户先点击修复按钮。
- 区分普通启动与更新迁移，按版本或签名身份记录迁移结果，避免每次启动重复重置。
- 只处理 Yisi 对应的授权，不清除配置、密钥、历史或其他应用的权限。
- 重置不能代替授权；需要用户确认的 macOS 授权仍由系统完成，并保留引导进度。
- 固定自签名证书属于待验证方案，需通过实际跨版本升级测试确认授权表现。

## 软件修复入口

- 名称为“修复软件”，面向功能失效、配置异常和权限异常，不限于权限修复。
- 必须保留翻译历史数据库、历史截图和学习数据；不能直接复用 `fresh-start.sh --new`。
- 默认保留 API 密钥及配套服务地址、模型配置，避免修复后用户失去服务访问。
- 优先检查与修复，必要时备份并恢复普通设置的默认值，再重新启动。
- 清除 API 配置可以作为独立可选操作，不能隐含在默认修复中；具体交互待确定。
- 发布前验证旧版覆盖升级、授权拒绝、迁移失败和修复后历史可读的情况。
