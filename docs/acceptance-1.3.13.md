# 1.3.13 验收清单

本版提供标准 DMG 和辅助安装 ZIP。辅助安装不会
自动授予录屏、辅助功能权限，也不保证免除所有 macOS / 企业管理策略的限制。
两个包使用完全相同的 ad-hoc 签名应用，支持 Intel / Apple Silicon，最低 macOS 14。

## 安装包

GitHub Release（本地构建后亦可在 `build-app/Acceptance-1.3.13/` 验收）提供：

- `Yisi.dmg`：拖入 Applications，首次打开按系统“仍要打开”流程。
- `Yisi-Assisted.zip`：完整解压，退出 Yisi，双击 `Install Yisi.command`，
  阅读路径和说明后输入 y。仅解除新安装副本自身的下载隔离，不使用 sudo。
- `SHA256SUMS.txt`：在同一目录执行 `shasum -a 256 -c SHA256SUMS.txt`。

辅助脚本若被系统拦截，终端输入 `/bin/bash `（末尾有空格），拖入脚本再回车。
脚本不是开发者签名/公证的替代品，正常隐私授权仍由用户操作。
旧版本保留在安装目录下 `.Yisi-previous.*/Yisi.app.disabled`，失败时尝试回滚。

## 配色

设置 → 通用 → 界面配色：五个无文字胶囊，顺序为原版紫、墨蓝、玉绿、暖红、柔金。
保持现有布局和圆角，不恢复已撤销的圆角对齐实验。分别检查深浅模式、玻璃开关、
预设浮层和高级自定义。主色、辅助色、选中背景、按钮文字和染色分别适配。
不会自动覆盖用户当前配色。恢复默认回到原版紫色。

## 翻译源

设置 → 翻译 → 其他翻译源：导入 JSON、审核地址、选择源；需要密钥时在此保存到
Keychain。该引擎仅提供普通翻译和本地 OCR，隐藏弹窗中的自定义提示与智能改进，
不会覆盖原来的 AI 设置。没有附带任何厂商 API 或真实密钥。

本地演示：

1. 运行 `python3 docs/examples/translation-bridge.py`。
2. 导入 `docs/translation-source.example.json` 并批准本机地址。
3. 点“测试翻译源”，固定测试原文 `Hello` 应返回 `你好`。
4. 关闭 bridge 再测试，应明确提示无法连接，不调用其他翻译引擎。
5. 修改 JSON 配置后重新加载，应要求重新批准。撤销授权后不能发送请求。

演示 bridge 只认识 Hello → 你好，用于协议验收，不是实际翻译服务。
复杂签名/OAuth 等由用户自己的 Agent 编写本地 bridge，Yisi 不执行脚本。
完整 schema、语言码和 Agent 接手步骤见 `docs/translation-sources.md`；
应用资源内也附带该指南和示例，翻译源右侧“…”面板中的“配置指南”可打开。
面板向下垂直展开，左边缘对齐“导入配置”，右边缘对齐“…”；开启玻璃时跟随
原生 Liquid Glass、染色及深浅模式。

## 权限引导

进入权限页不自动请求授权。点击“开启”只请求系统授权，不同时打开系统设置。
通过系统提示中的“打开系统设置”进入权限页；若之前拒绝或系统不再提示，
引导页提供单独的“打开系统设置”按钮。已有有效授权不主动重置。

## 已验证与边界

- Swift 测试 94 项、脚本测试 21 项通过。
- UI 实测本机请求成功、断线错误、授权确认；测试未改用户的实际翻译源和主题设置。
- 通用二进制两种架构均最低 macOS 14；签名、DMG、ZIP 内容和 SHA256 已校验。
- 脚本的 dry-run、取消、篡改包拒绝和打包内容均已测试，未改本机隐私授权。
- 未在每个 macOS 版本、实际浏览器下载隔离环境或企业管控设备上实机验证。
- 已检查完整翻译设置页及垂直浮层的布局；未为验证系统提示而重置现有隐私权限。
- 未替用户接入 Google、百度、腾讯等厂商；实际适配需用户凭据与服务端测试。
